5tratMux v0.9.42 corrects the remaining live hashrate paths and adds safe,
OS-coordinated service power control.

Miner and fleet displays now use recent hardware telemetry first. Avalon
firmware's lifetime `MHS av` field is never used: the one-minute hardware rate
is preferred, with five-minute and longer compatibility fallbacks only when a
firmware omits the shorter field. Fresh zero/standby telemetry is authoritative
and can no longer revive an older non-zero share estimate.

When hardware telemetry is unavailable, accepted proofs are now a bounded
fallback built from explicit one-minute and five-minute windows. The blended
estimate is recalculated on every status response and all samples expire after
five minutes. The fleet headline no longer substitutes the old proof-derived
summary when the correct visible total is zero.

The System page includes a confirmed **Power off 5tratMux** action. 5tratumOS
owns the privileged lifecycle, keeps settings, licence state and saved miner
allocations intact, and presents a dedicated power-on screen while the service
is stopped. Users can choose whether miner firmware should use its existing
saved fallback pools during downtime and whether saved miners should reconnect
when MUX returns. Miner administration credentials are never retained.

The complete 460-test MUX suite and 104-test OS suite passed. Native AMD64 and
ARM64 packages passed protected-runtime and health verification. The corrected
AMD64 DEV package was exercised on the `.235` node: the Avalon Q reported zero
in hardware standby, four connected miners used current hardware telemetry,
and disconnected miners were excluded from the MUX fleet total.

The updater preserves wallets, application data, local settings, licence and
trial state, miner identities, saved pools and routing configuration.
