# 5tratMux 0.9.55 — Miner discovery and connection guidance

Setup now shows an identified CGMiner-compatible miner even when its firmware
does not support Mux's automatic pool configuration. These devices receive
manual connection instructions; discovery never attempts an unsupported pool
write. A rejected or unavailable pool-settings read no longer hides a valid
miner identity. Configuration still requires a successful settings read where
needed to preserve existing pools.

Mux acknowledges the miner's local authorization before route preparation and
upstream negotiation. This reduces the risk of miners with short authorization
deadlines abandoning Mux while a route is being prepared. Each upstream pool
must still authorize successfully before work is forwarded. Rejection,
authorization timeout and excessive pre-authorization buffering close the
failed route rather than presenting unauthenticated work as usable mining.

Setup includes the full onboarding sequence:

1. Check Mux access and an enabled, healthy pool for the miner's algorithm.
2. Scan the LAN or check the miner's IP. If its management API is unavailable,
   continue with manual connection.
3. Review and confirm supported automatic configuration, or enter the displayed
   Mux pool URL, unique username/worker and password in the miner's own settings.
   Save and reconnect, retaining previous pools as fallbacks.
4. In **Miners**, select the connected worker, choose pools totalling **100%**,
   and select **Apply allocation**. Verify a live route and accepted shares.
5. Optionally select that miner in **AI Automation** and enable or update the
   desired mode.

Workers appear in Miners when they connect. **ADD** selects an existing miner
for a shared allocation; it is not a registration step. `MyMiner` is a valid
SHA256 example, not a mandatory worker name. Give each miner a unique name;
manual Scrypt workers use `scrypt.YOUR_WORKER` on the same Mux port.

The live view now says **No live route** when there is no active session and
directs users back to Setup, instead of showing **Choosing route / Dedicated
route** for an offline worker. Empty scans explain that management discovery
and manual Stratum connection are separate. Local AI is optional for basic
routing and can remain off when another AI provider is selected.

This is a Mux application update; no companion OS or pool-app update is required
for these changes. Existing licence, routing and application state are retained.
The release includes the Local AI network and model recovery changes from
0.9.54.

A miner without an accessible supported management API can still require manual
setup. These changes address reproducible discovery and handshake issues; they
do not establish that every reported connection failure has the same cause or
that the reporting user's miner has been tested successfully.
